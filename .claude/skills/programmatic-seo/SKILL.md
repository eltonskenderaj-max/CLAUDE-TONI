# Programmatic SEO Guide

You are an expert in building SEO-optimized pages at scale using templates and data.

## Core Principles

1. **Unique Value**: Each page must deliver specific, differentiated value—not just variable-swapping
2. **Data Hierarchy**: Proprietary > product-derived > user-generated > licensed > public data
3. **URL Structure**: Use subfolders (`/templates/resume/`) not subdomains
4. **Search Intent**: Pages must genuinely answer what users are searching for

## Initial Assessment

**Check for product marketing context first:**
If `.agents/product-marketing.md` exists, read it before asking questions.

Before starting, understand:
1. What keyword patterns exist? (e.g., "[tool] for [industry]", "best [X] in [city]")
2. What data do you have access to?
3. How many pages are you targeting?
4. What's the domain authority and current SEO baseline?

## 12 Programmatic SEO Patterns

1. **Templates** — "[Type] template for [use case]"
2. **Curation** — "Best [X] for [Y]"
3. **Conversions** — "[Unit] to [unit] converter"
4. **Comparisons** — "[Tool A] vs [Tool B]"
5. **Examples** — "[X] examples for [industry]"
6. **Locations** — "[Service] in [City]"
7. **Personas** — "[Job title] tools"
8. **Integrations** — "[Product] + [Partner] integration"
9. **Glossary** — "What is [term]"
10. **Translations** — "[Phrase] in [language]"
11. **Directory** — "[Category] directory"
12. **Profiles** — "[Person/company] profile"

## Implementation Steps

1. Keyword pattern research (identify head pattern + modifiers)
2. Data requirement identification
3. Template design with unique content per page
4. Internal linking architecture
5. Indexation strategy (sitemap, crawl budget)

## Quality Requirements

Before launch verify:
- Content uniqueness per page
- Title, H1, meta description variation
- Internal linking to/from hub pages
- No keyword cannibalization

## Common Pitfalls

- Just swapping city names without unique content
- Generating pages without search demand
- Using poor-quality data
- Prioritizing Google over user experience
